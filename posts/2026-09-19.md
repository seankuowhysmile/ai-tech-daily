# AOSP 名存實亡？Android 17 的私有化 API 如何撕裂開源生態系

> 原始報導：[Android 17 is the first since 3.x to add new APIs without releasing to the AOSP](https://grapheneos.social/@GrapheneOS/117282080803799576)　—　HackerNews

## 一句話看懂

注重隱私的 GrapheneOS 開發團隊指出，Android 17 成為自 3.x 版本以來，首個未將全新 API 代碼釋出至 AOSP 的重大版本，標誌著開放原始碼 Android 的轉折點。

## 這件事的技術與產業意義

Android 長期仰賴「AOSP 開源核心加上 GMS 閉源套件」的雙軌架構，讓硬體廠商與第三方 ROM 開發者能基於底層開放源碼建構客製化系統。然而，隨著系統層級功能與 Google 服務綁定愈加緊密，過往由底層框架提供的公開 API，如今被大規模移往 Google Play Services 或以私有二進位檔發布。

在 Android 17 中，部分關鍵功能與全新 API 乾脆直接跳過 AOSP 開源代碼庫。這意味著第三方 ROM（如 LineageOS、GrapheneOS）以及不搭載 GMS 的海外硬體廠商，將無法透過標準原始碼編譯出具備完整相容性的現代 Android 環境，迫使整個生態進一步走向二進位逆向工程或被動依賴封閉介面。

## Hacker News 社群怎麼看

這在 Hacker News 上毫無意外引發了「Android 到底還算不算是開源專案」的激烈激辯。不少開發者認為，Google 早就把 Android 當作特洛伊木馬，先用開源吸引硬體廠商與生態紅利打下全球市占，如今收網將 API 轉為封閉資產以防堵外部挑戰者，只是預料之中的商業必然。

然而，開源純粹派則發出警訊：一旦 AOSP 淪為空殼，全球將失去唯一具有規模的開源行動作業系統基石。這不僅扼殺了隱私導向系統的生存空間，也讓歐盟等反壟斷監管機構有了全新且極具殺傷力的調查切入點。
