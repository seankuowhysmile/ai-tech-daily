如果你看得到這一頁，代表建置流程已經正常運作了。這篇文章本身就是說明書 —— 讀完你就知道怎麼發下一篇。

## 怎麼新增一篇文章

在 `posts/` 資料夾裡放一個 `.md` 檔就好，例如 `posts/my-second-post.md`。存檔之後重新建置，它就會自動出現在首頁列表最上方（依日期排序，新的在前）。

檔案最上方那段被兩行 `---` 夾起來的東西叫做 **front matter**，用來描述這篇文章：

```yaml
---
title: 文章標題
date: 2026-09-05
description: 顯示在首頁列表的摘要，不寫的話會自動抓內文開頭。
draft: true
slug: custom-url-name
---
```

五個欄位**全部都可以省略**，各自有合理的預設值：

| 欄位 | 省略時會怎樣 |
| --- | --- |
| `title` | 抓內文第一個 `#` 標題，再沒有就用檔名 |
| `date` | 抓檔名的 `YYYY-MM-DD-` 前綴，再沒有就在終端機警告並排到最後 |
| `description` | 自動擷取內文前 120 字（會先去掉 Markdown 語法） |
| `draft` | 預設 `false`。設成 `true` 這篇就完全不會被輸出 |
| `slug` | 用檔名產生。網址會是 `/posts/<slug>/` |

> 建議檔名用英文。中文檔名可以動，但網址會變成一長串百分號編碼，很難分享給別人。

### 關於日期

`date` 刻意**不會**去讀檔案的修改時間。原因是 `git clone` 不保留檔案時間戳記，如果拿它當預設值，你的網站每次在 GitHub Actions 上重新建置時所有文章都會變成「今天」，排序整個崩掉。所以寧可警告你，也不要猜。

## 圖片要放哪裡

有兩種擺法，你可以混著用：

1. **純文字文章** —— 直接放 `posts/my-post.md`
2. **有附圖的文章** —— 建一個資料夾 `posts/my-post/`，裡面放 `index.md` 和圖片

第二種的好處是圖片路徑非常單純：圖片跟文章放在一起，你就直接寫 `![說明](photo.png)`，不用去算 `../../` 要幾層。建置時整個資料夾會原樣複製過去，所以你在編輯器裡看到的路徑跟瀏覽器裡的路徑**完全一致**。

另外還有一個 `static/` 資料夾（需要時自己建立），裡面的東西會原樣複製到網站根目錄，適合放 `favicon.ico`、`CNAME` 這類全站共用的檔案。

## 兩個指令

```bash
pnpm dev     # 開發模式：自動重建 + 瀏覽器自動刷新
pnpm build   # 正式建置：產出乾淨的 dist/
```

寫文章的時候開著 `pnpm dev`，存檔瀏覽器就自己更新了，不用按 F5。
